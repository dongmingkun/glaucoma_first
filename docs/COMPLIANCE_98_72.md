# 98.72 三模型包 · 按组委会模板 F1/F2/F3 实测（T4，2026-11-10）

> 关联：#213（本单）、#211（首轮 T4）、#97（复赛包红线）、#206（98.87 核验材料 PR）。
> 本版按《模型核验材料与数据申明清单模板》的 **F1/F2/F3 原文口径**复测，替换首轮里
> “单轮热缓存 p50/p95”与“冷进程 147ms”两个非模板口径的表述。
> 结论：**98.72 包 F1 平均 96.61ms、F2 0/100、F3 475.82MB，三项均过线**；
> 但它只对应 98.72，**98.87 仍然没有合规包**。

## 0. 结论

| 模板项 | 口径（模板原文摘要） | 实测 | 判定 |
|---|---|---|---|
| **F1** | batch=1 串行，100 张连续 3 轮，逐图 3 轮取均值再对 100 张平均；含预处理/后处理，**不含模型加载与预热** | **96.61 ms/图**（p50 94.70，p95 108.15，max 147.63；**cache512 输入，原图会更高**） | ⚠️ 缓存图口径 ≤100ms（余量 3.4ms），原图未认证 |
| **F2** | cost.py 与 predict.py 同一 `load_model/run_group`，eval、关随机增强，100 张逐张比对 | 二值不一致 **0/100**；排序不一致 **0**；max\|Δp\| **5.0e-06** | ✅（≤1e-3） |
| **F3** | 推理实际加载的权重及必要配套文件，解压后 ≤500MB；项目代码不计入 | 3 权重 **475,820,470 B = 475.82 MB**（含 predict.py 的包体 475,834,604 B） | ✅ |
| 精度（A6） | 与 F1 一致 | FP16（CUDA AMP autocast） | — |
| 与官方 98.72 CSV（`b664…`）逐字节一致 | — | **未验证**（缺原图） | ❌ 不可比 |

**F1 的边界要说清**：96.61ms 是三轮平均；第 1 轮 120.74ms、第 2/3 轮 84.54/84.56ms。
首轮慢是 Kaggle 私有 dataset 挂载点冷读（95 张图首次 stat/read）叠加 GPU 时钟爬升，
不是模型本身。若官方复测时图片在本地且已预热，应落在 84–85ms；若把冷读计入，就是 96.61ms。
另：**如果把 3 个模型的加载时间也算进单图**，100 图冷进程是 147ms/图（见 §5），
模板明确“不含模型加载与预热”，故该数不计入 F1，仅作参考。

**最重要的保留**：本次 F1 用的是 `cache_all/test` 的 **512×512 缓存图**；官方 F1 会用原始
test 图（分辨率更高、JPEG 解码更慢）。同一包在 RTX 5060 上用原图约 71ms/图，T4 约为其
1.3–1.5 倍，原图口径很可能落在 95–110ms。因此 **96.61ms 是偏乐观的下界，不能据此宣称
“T4 + 原图已认证 ≤100ms”**；要认证必须拿 5855 张原图按同一协议再测一次。

## 1. F1：推理耗时（模板口径）

测试配置：

- 硬件：Tesla T4 16GB；torch 2.11.0+cu130；FP16 AMP。
- 模型：`cb384.pt` + `cs_hi512_all.pt` + `cs_hi512_all_ra.pt`，等权 1/3，TTA1。
- 数据：`cache_all/test` 前 100 张（官方 `test.csv` 顺序），batch=1，prep-worker=1（保守）。
- 计时：每图 `run_group([path], age, members, tta=1, batch=1)` 前后 `cuda.synchronize()`；
  含 JPEG 解码、眼底裁剪、归一化、3 模型前向、概率平均；不含模型加载；预热 5 张不计入。
- 轮次：同一 100 张连续跑 3 轮，逐图取 3 轮均值，再对 100 张取平均。

结果：

```text
round1 mean=120.74  p50=117.73  p95=145.45
round2 mean= 84.54  p50= 83.59  p95= 94.54
round3 mean= 84.56  p50= 83.32  p95= 94.79
F1（逐图三轮均值后平均）= 96.61 ms
p50 94.70 / p95 108.15 / max 147.63
```

模板判定线：平均 >100ms 才需要限期复测一次；>150ms 直接不认定。本次 **96.61ms**，
按原文口径通过，但余量只有 3.4ms，且 p95 已过 100ms（首轮冷读所致）。不建议对外宣称“大幅余量”。

## 2. F2：cost.py 与 predict.py 一致性（模板口径）

cost 路径直接 `import predict.py`，调用同一个 `load_model` / `run_group`；模型 `eval()`，
无随机增强、无 dropout、无采样，推理路径本身无随机算子（脚本未显式设种子，结果不受影响）。

100 张逐张比对（cost 路径 vs `predict.py` CLI，均 TTA1、batch=1）：

| 指标 | 结果 |
|---|---|
| 二值判定不一致 | **0 / 100** |
| 概率排序不一致（名次变化张数） | **0 / 100** |
| 概率排序不一致（两两逆序对） | **0** |
| 单张概率最大绝对误差 | **5.00e-06** |
| 平均绝对误差 | 2.40e-07 |

模板要求二值/排序不一致为 0、|Δp|≤1e-3；三项均满足。

**注意**：这是包内 `cost.py` 路径与 `predict.py` 路径的一致性，不是“包 vs 官方 98.72 CSV”的
一致性。后者仍缺原图（§4）。

## 3. F3：包体（模板口径）

模板只计“最终测试集推理实际加载的权重及必要配套文件”，项目代码不计入：

| 文件 | 字节 | 说明 |
|---|---|---|
| `cb384.pt` | 176,328,125 | ConvNeXt-Base@384，train-only，FP16 |
| `cs_hi512_all.pt` | 199,660,651 | ConvNeXt-Small@512，train+all，FP16 |
| `cs_hi512_all_ra.pt` | 99,831,694 | ConvNeXt-Small@512，train+all + RandAugment，FP16 |
| **F3 合计** | **475,820,470 B = 475.82 MB = 453.79 MiB** | ≤500MB ✅ |
| （参考）`predict.py` | 14,134 | 项目代码，按模板不计入；计入后包体 475,834,604 B |

无独立 config / 归一化统计量 / 类别表文件（均内嵌在 checkpoint 与脚本常量中）。
三个权重均从公开 Release 下载并逐个核对 SHA-256（见 §6 与 `t4_run.log`）。

## 4. 为什么仍不能复现官方 98.72 CSV

### 4.1 数据侧已复核：只有 cache512，没有原图

`linglingyusc/glaucoma` 是**私有**数据集（owner=linglingyusc，`isPrivate=true`），完整结构：

| 目录 | 文件数 | 大小 | 规格 |
|---|---|---|---|
| `cache_all/train` | 57,245 | 2,359,039,885 B | 512×512 RGB |
| `cache_all/test` | 5,855 | 241,764,320 B | 512×512 RGB |
| 合计 | 63,100 | 2,600,804,205 B | — |

没有 `valid/`，没有原始分辨率 test 图。复核脚本与日志见 #212（`g212-list-glaucoma-dataset`）。
因此无法用官方原图管线重跑，`b664…` 的逐字节复现在本机/Kaggle 现有数据上不可完成。

### 4.2 cache512 输入的全量输出

同一包在 5855 张 cache512 上跑通：

```text
5855 行，CRLF，158,120 B
md5    ae4200bf296276a834516cbf2e72c26e
sha256 d2447a748e9a40ebc29e95be9dd5857ecf6da714e7fd40d9993a78271c4abb42
wall   531.4 s = 90.76 ms/图（含 5855 次挂载 stat 约 166 s；推理循环 61.1 ms/图）
```

与 ens10（98.82 固化件）：rank Spearman **0.9431**、标签一致率 **97.54%**、均值 0.0527（ens10 0.0830）。
`submit_pkg/README.md` 对 3 模型子集的预期就是“与 ens10 排序相关约 0.94”，
所以 0.9431 属正常范围，不是异常；但这份 CSV **不能提交**，md5 也不能与 `b664…` 比对。

## 5. 参考：冷进程 147ms（不计入 F1）

同一包、同一 100 图，`python predict.py ... --tta 1 --batch-size 1 --prep-workers 8` 三次：
14.932 / 14.571 / 14.601 s → **147.0 ms/图**（含 3 模型加载约 3s 与 100 次挂载 stat 约 3s）。
若官方把“每张图重新加载模型”也算进端到端，这个包在 T4 上不可能过 100ms；
按模板 F1（不含加载与预热）则以上述 96.61ms 为准。两个口径同时给出，避免误读。
